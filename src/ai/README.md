# 模型调用边界

业务代码通过 `createModelClient(connection)` 调用模型，传入业务请求和取消信号：

- `generate(request, signal)`：讨论、概览、解释、图表和公式识别；统一返回文本增量与用量。
- `translate(request, signal)`：翻译文本；保留异步文本回调、诊断信息和现有重试语义。

请求参数由 `model-request.ts` 定义。供应商的 URL、鉴权、请求 JSON、SSE 和响应解析留在 `provider.ts`、`translation-provider.ts`。业务模块不按协议分支，也不直接调用这两个传输实现。并发槽、冷却、取消和失败回调仍由原有模型层处理。

`model-configuration.ts` 提供不联网的配置与能力查询。配置保存、真实请求路由以及状态展示共用这里的校验和选择规则。`modelConfigurationStatus(view, feature?)` 只返回配置状态、名称或原因，不返回密钥、接口协议或请求格式，也不表示网络连通性已验证。

未指定功能的状态查询展示全局默认模型；未设置默认模型时沿用请求层的回退顺序。指定功能后使用该功能的路由和启停状态。生成支持四种已实现协议；翻译仍限于已实现的两种协议。翻译不支持某个模型，不代表该模型不能用于讨论或概览。

配置编辑页需要协议字段来设置接口；历史记录中的接口快照用于恢复、诊断和判断缓存是否仍适用。这些用途保留。其余界面只消费模型层返回的状态。

新增供应商时，在模型层实现传输并登记能力，同时验证配置状态、真实路由、流式完成、失败及取消。不要在弹窗、阅读器或其他业务模块另加协议白名单。
